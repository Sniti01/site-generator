## 3. `robots.txt` и `.htaccess` — целиком

`sites/7thserpent.com/public/robots.txt`:

```
# robots.txt — www.7thserpent.com (7th Serpent)
#
# A static site (Astro). Every page is open to indexing: there is no admin
# area, no login, no on-site search, no pagination and no addresses with
# parameters, so there is nothing to disallow.
#
# What is deliberately NOT blocked (so nobody "fixes" it later):
#   /_astro/  stylesheets, fonts and images with a content hash in the name;
#             Google renders a page the way a browser does, and blocked CSS
#             looks to it like a page without a layout.
#   /404/     the error page; the server returns it with status 404 for every
#             missing page address, the sitemap leaves it out, and no page
#             links to it.
#   AI crawlers — they are not blocked either. Blocks that the hosting
#             provider or Cloudflare may prepend to this file on the live
#             server are not part of it (`npm run live:check` tells them
#             apart from this file).
#
# The Sitemap line carries the full address, because the file is also read
# from outside the domain. The canonical address is https WITH www (`site` in
# astro.config.mjs; the owner's decision П62 p. 4).

User-agent: *
Allow: /

Sitemap: https://www.7thserpent.com/sitemap-index.xml
```

`sites/7thserpent.com/public/.htaccess`:

```apache
# Server configuration for www.7thserpent.com (7th Serpent)
#
# Hosting: the same provider as the owner's first site (decisions П52 p. 1,
# П106). The file lives in public/, so Astro copies it into dist/ on every
# build and it travels with the site.
#
# What works here is known from the first site on the same hosting (measured
# 2026-08-26 on the neighbouring 7dtd.com.pl and 2026-09-15 on the first
# site, `x-ray … wal`): nginx stands in front and only requests for HTML
# reach Apache and this file. So the file holds only what Apache really does
# for this site:
#   WORKS:  ErrorDocument, the redirect to one https address, Cache-Control
#           for HTML.
# Rules for static files (CSS, fonts, images, the icons without a hash in
# their names, robots.txt, sitemaps) would be dead here: nginx serves those
# files, and their caching is set in the hosting panel (launch checklist).
# There are no dead rules in this file.
# Every directive sits in <IfModule>: on shared hosting a directive of an
# unknown module is not ignored, it takes the site down with error 500.
#
# LAUNCH ORDER (П52 p. 3, strict): the mailbox works → the domain is bound
# to this build → https check (`npm run live:check`) → Search Console.
#
# WHEN BINDING THE DOMAIN: the SSL certificate in the panel (Let's Encrypt)
# FIRST, traffic to this build AFTER — a redirect to https without a working
# certificate gives a page nobody can open.

# ─────────────────────────────────────────────────────────────────────────
# 404 page
#
# The error page is a page of the structure (`/404/`, type `legal`) and is
# built through the shared route into a folder — `dist/404/index.html`, not
# `dist/404.html`. Apache serves it for every missing page address with
# status 404 (an internal subrequest; the status stays 404). A missing static
# file (a picture, a stylesheet, an icon) never reaches Apache: nginx answers
# it with its own 404.
# ─────────────────────────────────────────────────────────────────────────
ErrorDocument 404 /404/index.html

# ─────────────────────────────────────────────────────────────────────────
# One canonical address: https, WITH www
#
# `link rel="canonical"` of every page and the sitemap addresses point to
# https://www.7thserpent.com/… (`site` in astro.config.mjs; П62 p. 4). The
# server leads there in a single 301 hop for http://, for the address
# without www and for http:// without www — never two hops.
#
# `%{HTTPS}` can be `off` despite the padlock in the browser when TLS ends at
# a proxy (here: Cloudflare), so the proxy's header is asked too; otherwise
# the redirect would loop.
# ─────────────────────────────────────────────────────────────────────────
<IfModule mod_rewrite.c>
  RewriteEngine On

  RewriteCond %{HTTPS} !=on
  RewriteCond %{HTTP:X-Forwarded-Proto} !=https
  RewriteRule ^ - [E=NO_HTTPS:1]

  RewriteCond %{ENV:NO_HTTPS} =1 [OR]
  RewriteCond %{HTTP_HOST} !^www\.7thserpent\.com$ [NC]
  RewriteRule ^(.*)$ https://www.7thserpent.com/$1 [R=301,L]
</IfModule>

# ─────────────────────────────────────────────────────────────────────────
# Caching of HTML
#
# HTML has no content hash in its name: `must-revalidate`, so that a
# correction reaches the reader on the next visit.
# ─────────────────────────────────────────────────────────────────────────
<IfModule mod_headers.c>
  <FilesMatch "\.html$">
    Header set Cache-Control "public, max-age=0, must-revalidate"
  </FilesMatch>
</IfModule>
```

Форма — как у первого сайта (П54 п. 5–6, П55 п. 2). Отличие одно — слова «missing page address» вместо «every missing
address» (`816ba46`, находка CL1-P-11): 404 статики у этого хостера отдаёт nginx, до `.htaccess` такие запросы
не доходят.

## 10. Открытые вопросы

### Технические — решены

1. **Нормализация сборки другой машины** — в сторожах (`sverka-dist`) и в `check-live` (HTML = сборка). Как считается:
   - значения cid — порядковыми метками по первому появлению в HTML;
   - имя CSS — хешем содержимого с этими метками (перестановка ссылок между CSS, различными только cid, видна);
   - остальное — побайтно.

   Проверено моделью сборки CI с настоящим компилятором. Политическая сторона — вопрос 1.
2. **Главная выкладывается последней.** Оборванная первая выкладка оставляет сервер без нашей главной, и повтор снова
   первый, со сверкой сборки. Раньше решали 7 ключевых имён из 165.
3. **Глубина по `find .` после суда корня.** Чужое внутри наших папок видно; робот с доступом ко всему аккаунту его
   целиком не обходит.
4. **Корпус на CI** — после `npm ci`: скрипты установки идут без сырья на диске. Сторож секретов — до выгрузки корпуса.
5. **Комментарии `robots.txt` и `.htaccess` сужены до «missing page address»:** 404 статики отдаёт nginx.
6. **Материалы скептиков** — в репозитории, кроме производной копии сборки CI (8 МБ) — её воспроизводит `sim-ci*.mjs`.
   Сырья корпуса и секретов в материалах нет (проверено поиском перед копированием).

### Политические — для вас

**Вопрос 1. Сверка сборки CI с принятой — после нормализации, а не буквально sha256 (SV1-Z-1, CL3-Z-1).** Буквальная
сверка на первой выкладке остановит её всегда: 20 файлов сборки раннера иные только значениями `data-astro-cid` ядра
и хешами имён CSS.

| Вариант | Что это | Цена |
|---|---|---|
| **(А) Нормализация — как сделано** (рекомендую) | sha256 после замены cid метками и имён CSS хешем содержимого; остальное побайтно; модель CI — проход | отступление от буквы П106; законная разница машин отделена правилом, а не доказана побайтно |
| (Б) Список принятой сборки — с CI | режим workflow «собрать без выкладки» публикует список сборки раннера; вы его принимаете, первая выкладка сверяет CI с CI буквально | ещё один режим workflow и один ручной запуск; «принятой в сессии» станет «принятой по списку CI» |
| (В) Убрать причину | ядро пакетом или своя сборка ядра: cid не зависит от папки checkout | архитектура (бэклог 71 п. 5); не к запуску |

Рекомендация — **(А) сейчас, (В) — когда ядро станет пакетом.** (Б) добавляет ручной шаг ради того же вывода.

**Вопрос 2. Длины `title` (15 страниц, 61–70 знаков) и `description` (10 страниц, 163–181).** (А) оставить до данных
Search Console после запуска; (Б) отдельной сессией снять хвост « — 7thserpent.com» из `title` и сократить
`description` — это договор страниц, `structure.json`. Рекомендация — **(А)**. Обрезается хвост с именем сайта, а имя
несёт `og:site_name`; `description` Google часто пишет сам. Решать по показам и CTR.

**Вопрос 3. `og:url`, `og:image`, `twitter:*` и типы schema.org по странице.** Голова печатается ядром, поэтому правка
идёт и в первый сайт; push в `main` по `core/**` запускает и `deploy-ac4bf`. `og:image` — это арт издателя в превью
соцсетей, а значит решение о классе лицензии. (А) отдельная сессия ядра после запуска второго сайта: `og:url` и
`twitter:card` — всем, `og:image` — кадр героя страницы, по вашему слову об арте в превью; (Б) оставить. Рекомендация —
**(А) после запуска.**

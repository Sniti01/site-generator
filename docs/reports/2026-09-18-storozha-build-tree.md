не изменилось ни на байт.

**Что стало — окончательная форма второго сайта** (после его раундов 2–4:
`7761402`, `470633f`), не промежуточная из `656d782`:

- `guard(c, where)` на якорь и каждое слияние: `no_page` → «якорем такой
  кластер не стоит, возврат — только полем» / «возврат объявляется полем
  «возвращено_из_no_page», не «слияния»»; `exclusions` → «не по теме;
  страница его не перекрывает».
- Ключ: судьба фразы — `fateOfPhrase` **тем же порядком, что раскладка**
  (кластерная фраза — строка кластера; «Некластеризовано» — своя строка;
  нет в выгрузке — null). `exclusions` → «ключом на страницу не берётся»;
  `no_page` — четыре диагноза: «Некластеризовано … поля возврата для
  отдельной фразы нет», «фраза кластера «X» … возврат — только полем,
  кластером целиком», «лишний — уже возвращён на эту страницу»,
  «возвращён из no_page целиком на Y; ключом не дробится». Ссылка на пачки —
  **П25** (пачки S0 первого сайта), не П65.
- Возвраты (`returnedTo`) собираются до сторожей ключей — иначе ключ раньше
  возврата по порядку страниц называл бы судьбу разведки, а не возврат.
- Комментарий `:221-225` заменён правдивым (`:287-289`).

**F1 — единственная существенная находка рецензии (раунд 1, линза 2):**
перенесённая с второго сайта `fateOfPhrase` читала строку `некластеризовано`

# 7. Факты, важные будущим сессиям

1. **Пачки первого сайта (П25) не перекрываются ничем, кроме поля
   `возвращено_из_no_page`** — ни якорем, ни слиянием, ни ключом; возврат —
   на кластер целиком; ключ на свою же возвращённую фразу — «лишний».
   То же, что у второго сайта (доклад сессии 5, факт 2).
2. **Сторож читает разведку тем же порядком, что раскладка:** у кластерной
   фразы — строка кластера, у «Некластеризовано» — своя строка. Любая новая
   проверка судьбы фразы обязана идти через `fateOfPhrase`, не через
   `phraseFate` напрямую.
3. **Пробы доказывают сторож только на тех конфигурациях, что есть
   в фикстуре.** Ожидание — полный текст с адресом; при добавлении сторожа
   — проба на каждую страницу-«исключение» (без якоря, с возвратом,
   `owner`, другой тип), иначе мутант «выключить при поле X» выживает.
4. **Инструмент точной замены сохраняет CRLF** — проверено байтами; heredoc
   в Git Bash пишет LF — только для LF-файлов. `sed -i` — никогда, даже
   для одной строки LF-файла (см. первую строку доклада).
5. **Две копии `build-tree` расходятся содержательно только в двух местах
   вокруг сторожей:** у второго сайта есть проверка «кластера нет
   в разведке» и цикл `no_page_ключи`, у первого — `судьбы`; после
   `2304aba` у первого `fateOfPhrase` кластер-первым, у второго — ещё нет.
   К выносу в ядро (бэклог 54 п. 2) обе копии должны сойтись.
6. **Боевая выгрузка первого сайта несёт 89 фраз с `google: 0`,** две из них
   стоят ключами (`ezio auditore collection switch`, `ubisoft ragnarok`) —
   фильтр по объёму в любом словаре фраз молча ослепит сторожа.

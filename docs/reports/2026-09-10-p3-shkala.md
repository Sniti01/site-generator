# 2026-09-10 · P3, правка шкалы: одна засечка на страницах игр

Ветка `phase-3`. Объём — решение П35 п.1: левая шкала на странице игры
показывает **только свою эпоху**. `IGLICA` и `STÓG` остаются краями.
Делается **до** приёмки глазами: проход по заведомо неверной шкале
пропал бы впустую.

**`npm run accept` — `40/40`, `exit=0`. `npm run gates` — `exit=0`.**

## Шаг 0: устройство шкалы, снятое до правки

| Что | Как устроено сегодня |
|---|---|
| засечки | `DescentRail` печатает по одной на каждую из пяти эпох, положение — `--at` |
| положение засечки | скрипт `place()` ставит её по центру слоя, найденного по `[data-era-section]`; значение из данных (`era.depth`) — только запасное, пока скрипт не встал |
| **ромб** | `.rail__marker`, положение — `--progress`, а он считается как `window.scrollY / scrollable` |
| активная эпоха | `IntersectionObserver` по тем же `[data-era-section]` |

**Ключевое наблюдение, которое проверю измерением:** ход ромба **не зависит
от засечек вовсе** — он считается от прокрутки страницы. Значит на странице
с одной засечкой ромб обязан ходить по всей шкале так же, как на главной.
Если измерение это опровергнет, скажу прямо.

**Вторая забота:** на странице игры сегодня **нет ни одного
`[data-era-section]`** — маршрут не передаёт этот крючок. Значит `place()`
не срабатывает и засечка стоит по запасному `era.depth`, посчитанному
для раскладки главной. Одной засечки мало: ей нужен якорь.

## Что делается

1. `DescentRail` получает пропс «какие эпохи показывать», по умолчанию — все
   пять. Разметка главной от этого не меняется ни на байт.
2. `Base.astro` пробрасывает пропс.
3. Маршрут передаёт эпоху страницы и вешает на ряд рассказа
   `data-era-section`, чтобы засечка встала по настоящему центру ряда,
   а не по чужому проценту.

## Ответ на вопрос владельца: ход ромба сохраняется. Измерено, не выведено

Пять замеров по странице игры, дорожка высотой 777,6 px:

| Доля прокрутки | `--progress` | Ромб от верха дорожки |
|---|---|---|
| 0 | 0,00 % | **0,0 px** |
| 0,25 | 25,00 % | **194,4 px** |
| 0,50 | 50,00 % | **388,8 px** |
| 0,75 | 75,00 % | **583,2 px** |
| 1 | 100,00 % | **777,6 px** |

Ход **строго линейный по всей длине**. Причина, снятая шагом 0 и
подтверждённая замером: положение ромба считается как
`window.scrollY / scrollable` и **от засечек не зависит вовсе**. Одна засечка
или пять — ромбу всё равно.

## Якорь оказался не формальностью, и вот число

Засечка встала на **29,64 %** дорожки — это настоящий центр ряда рассказа,
посчитанный скриптом `place()` по крючку `data-era-section`, который маршрут
теперь вешает. **Без крючка она стояла бы на 66 %** — это запасное значение
`era.depth` эпохи `karaiby`, посчитанное для раскладки главной, где слоёв
пять. Разница в 36 процентов дорожки: засечка указывала бы в пустоту.

## Как выглядит шкала с одной засечкой на полной высоте

`IGLICA` сверху, единственная засечка `1715` на 29,64 %, `STÓG` снизу, ромб
ходит по всей длине. Шкала читается как мера с одной отмеченной точкой,
а не как сломанный список: края на месте, ход есть, лишних годов нет.

**Про `toc` на вырост (П35 п.3):** правка ничего ему не перекрыла — ширина
полосы шкалы не менялась, разметка её осталась прежней. Но и места ему
не добавилось: шкала занимает узкий край, а `toc` потребует ширины, то есть
в сессии 6 понадобится решение о левой колонке, а не только о блоке.

## Ответ про мелкий заголовок секции `related`

**Это тот же вопрос 1 сессии 5, а не отдельный.** Секцию «Powiązane strony»
собирает маршрут своим `<h2 class="pokrewne__title t-title">`, потому что
`link-list` не объявлен в `blocks[]` этой страницы. Объяви его контракт —
секцию печатал бы блок ядра со своей ролью заголовка, и мелкость исчезла бы
вместе с причиной. Вариант **(б)** моей прежней рекомендации закрывает оба.

## Шаг 0 второй правки, записан до первой строки кода

**Что держит отступ.** `Base.astro` объявляет глобально
`@media (min-width: 1200px) { body { padding-left: var(--rail) } }` — контент
уступает место шкале. Снять шкалу и оставить отступ значило бы получить
фантомный жёлоб в 84 px.

**Что делается.**

1. `Base` получает пропс «печатать ли шкалу», по умолчанию — да.
2. Когда шкала не печатается, на `<body>` вешается класс, и правило рядом
   гасит отступ. **Класс вешается на отсутствие, а не на наличие** — тогда
   разметка главной не меняется ни на байт.
3. Пропс `epoki` у `DescentRail` и крючок `data-era-section` у маршрута
   **откатываются**: под вариантом В они мертвы, а мёртвый код — то же самое
   умолчание, только в коде.

## Прогноз

| Величина | Ожидание |
|---|---|
| правил CSS | **334 → 335**: одно новое правило гашения отступа |
| главная, `<body>` | **без класса**, разметка не меняется |
| главная, `index.html` | меняется **только именем листа** — CSS тронут, значит хеш новый |
| главная, пиксель | **ноль, семь кадров** |
| страница игры | шкалы нет; контент сдвигается влево на 84 px — намеренно |

**Провал:** любое расхождение пикселей главной; появление класса на `<body>`
главной; остаток отступа на странице игры.

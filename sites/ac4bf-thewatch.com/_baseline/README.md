### Файлы рядом с кадрами

`geometria.json` — условия съёмки (`clientWidth`, `clientHeight`, `dpr`),
`отступ_блока`, высота страницы и `offsetTop`/высота каждого якоря
на каждом вьюпорте; служебные ключи `снято`, `сборка`, `драйвер`. **Сверяется
`check` первым**: другой драйвер или другой отступ — одна строка вместо
списка сдвигов. `ne-sudyi.json` — кадры, временно не являющиеся судьями;
**после перебазирования пуст** у обеих страниц, число печатается при каждой
сверке. **С П46 (2026-09-12) список — печать для карты диффов, не вердикт:**
кадр из него сверяется и печатается «НЕ СУДЬЯ … N различий» своей графой,
чтобы таблица диффов по месту не считала его дифф находкой; код возврата
`check` он не меняет и не смягчает. `szum.json` — зоны шума числом (П45,
с 2026-09-12): по нему `check` судит пиксели, см. «Зоны шума».

## Как наводятся оконные кадры

**Кадр слоя наводится по якорю, а сдвиг сверху ловится числом** — П39,
новая редакция П30 п.2, исполнена 2026-09-11 пунктом 14 бэклога. Прокрутка
центрирует слой в окне: `y = round(offsetTop + (высота слоя − высота окна) / 2)`,
где `offsetTop` и высота берутся с живой страницы из `getBoundingClientRect()`
с точностью 0,01 (`К_ЯКОРЮ` в `core/accept/frames.mjs`), а округление стоит
снаружи — `offsetTop` дробный у четырёх слоёв из пяти, цель прокрутки целая.
Правило центрирования то же, что дало литералы 2026-09-09; арифметика
другая (тогда складывали целый `offsetTop` и округлённую половину), и на
дробных входах результат может отличаться на 1 px. Судья от этого
не страдает: обе стороны любой сверки идут через один скрипт.
Защита прежней редакции не снята, а **перенесена в число**: съёмка
записывает геометрию в `geometria.json` рядом с кадрами, и
`npm run accept:frames -- check` сверяет её с `geometria.json` эталона,
называя каждый сдвиг отдельной строкой `СДВИГ` — с видом: выше слоя, внутри
слоя или высота страницы. Условия съёмки сверяются первыми: видимая полоса
прокрутки отнимает у раскладки 10 px и на 390 меняет высоту страницы
(измерено 2026-09-11: 11545 против 11514) — это другой драйвер, не правка,
и печатается одной строкой вместо списка сдвигов.

> **Прежняя редакция, П30 п.2 (2026-09-09 → 2026-09-11), оставлена рядом,
> а не удалена — дословно; цитата — весь абзац ниже.**
>
> **`scrollY` — литерал, а не «где встало».** Числа получены центрированием слоя в окне 900 px на съёмке:
> `offsetTop + round((высота секции − 900) / 2)`, где `jerozolima` 879 + 13,
> `wlochy` 1805 + 13, `londyn` 5968 + 38. Но дальше они **фиксированы как
> литералы** и пересчёту не подлежат: сдвиг геометрии выше слоя обязан
> проявиться расхождением кадра, а не молча уехать вместе с новым
> `offsetTop`. Прокрутка выполняется ровно к записанному числу,
> и совпадение `window.scrollY` с ним проверяется до съёмки.

Литералы снятой таблицы 2026-09-09: **892**, **1818**, **6006** при `offsetTop`
879 / 1805 / 5968 и высоте страницы 8819. Почему сменено: смена гарнитуры
(шаг Ш) укоротила страницу на 186 px, и три кадра показали 20,1 %, 28,3 %
и 46,5 % различий, ни одно из которых не называло причину. Судья, который
на любой правке высоты выдаёт «катастрофу», перестаёт быть судьёй.

**Кадр блока наводится от заголовка** — П41 ответ 5, 2026-09-11. Формула:
`y = max(0, round(offsetTop заголовка − ОТСТУП_БЛОКА))`, `ОТСТУП_БЛОКА` = 100 —
`--header-h` (68) + `--space-lg` (32), то есть куда сама страница ставит
заголовок по клику якоря оглавления (`scroll-margin-top`). Под липкой шапкой
(коробка 69 px: 68 + линия) остаётся 31 px воздуха. Якорь — `id` заголовка
(`…-tytul`): секции блоков своих `id` не несут. **Остаток окна под коротким
блоком занимает следующий блок или подвал — кадр судит и их**; таблица
маппинга «кадр → пункт» обязана это учитывать: дифф в кадре вердикта может
прийти из правки списка ссылок под ним, дифф в кадре призыва — из подвала.
Число входит в определение кадра и пишется в `geometria.json`
(`отступ_блока`); другой отступ — другой драйвер, не правка.

## Порядок съёмки оконных кадров

Продолжает порядок `MIGRATION.md` §6, шаги 1–5, и выполняется **после них**,
на той же загруженной странице, без перезагрузки. Полный текст —
`npm run accept:frames -- protocol`. Драйвер — со скрытой полосой прокрутки
(`--hide-scrollbars`), `deviceScaleFactor` 1. **С 2026-09-12 драйвер —
Playwright MCP (headless Chromium)**; `clientWidth` 1440/390 подтверждён
геометрией. **Порядок по факту, отклонение от шага 1 (пункт 19 бэклога):**
`ПРОКРУТКА` выполняется ДО `ГОТОВНОСТЬ`, а ожидание картинок накрыто сроком
3 с на кадр с печатью числа недождавшихся (0 из 16 и 0 из 4 в обеих
съёмках); иначе `ГОТОВНОСТЬ` виснет на ленивых картинках. `frames.mjs`
не правился — правка судьи ждёт своей сессии.

1. `ГОТОВНОСТЬ` и `ПРОКРУТКА`: шрифты готовы, все изображения загружены
   (главная — 16 из 16, игра — 4 из 4), `scrollY` вернулся в 0. Затем
   `ГЕОМЕТРИЯ` с якорями из таблиц выше — слои и заголовки блоков; результат
   ляжет в `geometria.json` рядом с кадрами.
2. Снять первый экран 1440×900 и полный кадр 1440.
3. Для каждого слоя: `К_ЯКОРЮ(<якорь>)` — `behavior: 'instant'`, потому что
   `global.css` ставит `html { scroll-behavior: smooth }`; нет якоря —
   скрипт отказывает. **`scrollY` равен `ожидали` точно, иначе стоп.**
   Дать переходам осесть — 700 мс плюс два `requestAnimationFrame` (иначе
   кадр снимается посреди перехода, см. ниже). Снять оконный кадр.
4. Для каждого заголовка блока: `К_ВЕРХУ(<якорь>)` — заголовок на 100 px
   от верха окна; `scrollY` равен `ожидали`, иначе стоп; осадка; оконный кадр
   `baseline-desktop-blok-<якорь без -tytul>-1440x900.png`.
5. Сменить вьюпорт на 390×844 без перезагрузки (П16), `ПРОКРУТКА`
   и `ГЕОМЕТРИЯ` ещё раз, снять первый экран 390×844 и полный кадр 390.
6. Сложить обе геометрии и `отступ_блока` в `geometria.json` рядом с кадрами.
7. `npm run accept:frames -- check <кадры> <эталон>`: строка `ГЕОМЕТРИЯ`
   **цитируется в докладе дословно**. С 2026-09-12 (П45) код возврата
   `check` вердикт **несёт**: пиксель вне зон `szum.json` или выше их `макс`,
   разошедшиеся размеры, не снятый кадр — `exit 1`; `СДВИГ` геометрии сам
   по себе кода по-прежнему не меняет (`docs/11_PRIEMKA.md`, пункт 26
   бэклога), но тот же сдвиг обычно приходит `exit 1` через пиксели —
   разошедшиеся размеры полного кадра, дифф оконного. Каждый `СДВИГ`
   называет, **что и на сколько**: «выше слоя», «внутри слоя», «страница».
   Сдвиг не регрессия сам по себе, но обязан быть объяснён правкой, которая
   его дала. Строка «условия съёмки другие» или «отступ кадров блоков
   другой» — другой драйвер: сперва уравнять драйвер, а не искать правку.
8. **Контроль.** Второй прогон на той же сборке; расхождением вёрстки
   считается только то, что переживает контроль (зоны шума — ниже).

Липкая шапка при `scrollY > 0` перекрывает верхние 69 px (68 + линия) —
это часть настоящей страницы и часть эталона.

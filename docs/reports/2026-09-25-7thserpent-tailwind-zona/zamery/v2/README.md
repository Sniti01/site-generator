# Протокол маркеров, второй проход (v2)

Второй проход сделан исправленным `markery.mjs` (после раунда 1 «судью судят») и с записью
sha256 пяти файлов перед каждой сборкой (находка zona-3 раунда 1).

| Файл | Что в нём |
|---|---|
| `sha-0-iskhod.txt` | sha256 пяти файлов на `70195ca` до маркеров |
| `sha-A.txt` | состояние A: `global.css` взят из `main` (`git checkout main -- …`), маркеры 71–74 стоят |
| `sha-B.txt` | состояние B: `global.css` возвращён из `HEAD` (`git checkout HEAD -- …`), маркеры стоят |
| `sha-C.txt` | после отката маркеров: `sha256sum -c` против `sha-0-iskhod.txt` и `git status --short` |
| `markery-A.txt`, `markery-B.txt` | вывод `markery.mjs` по сборкам A (`--est 71,72,73 --net 74`) и B (`--est 71,72 --net 73,74`) |
| `sborki.txt` | строки гейтов и сторожей трёх сборок (A, B и чистая C) |
| `sverka-css.txt`, `.json` | сверка листов сборки `main` со сборкой C исправленным `sverka-css.mjs`, `--schet 20:19` |
| `stili-s2.json` | вычисленные стили, прогон `s2` исправленным генератором |

**Как читать строку 8 файлов `sha-A.txt` и `sha-B.txt`** (находка r2-markery-4 раунда 2): команды
двух состояний были разными. В A строка `0` — вывод `grep -c "@source not"` по `global.css`: директивы
нет (файл равен `main`, строка выше). В B на этом месте — вывод `grep "@source"`: две строки
директив, вторая — `@source not '../content';`. Состояние файла в обоих случаях держит sha256
в строке 2; сами файлы материалов не переписывались.

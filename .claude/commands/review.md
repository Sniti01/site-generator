Завершение цикла сессии site-generator в режиме human-on-the-loop.
Аргумент (если задан) — путь к отчёту: $ARGUMENTS. Если не задан — самый
свежий файл в docs/reports/.

По порядку:

1. Прочитай CLAUDE.md, DECISIONS.md, docs/BACKLOG.md, план фазы
   (docs/02_CLAUDE_CODE_TASK.md, docs/REUSE.md §6) и отчёт.

2. Не верь отчёту на слово — перепроверь дешёвое: код возврата
   `npm run gates -w ac4bf-thewatch.com`; `git status` чист;
   `git ls-files --eol` по изменённым файлам даёт `i/` = `w/`; ветка
   запушена (`git log origin/<ветка>..<ветка>` пуст). Расхождение отчёта
   с фактом — политический вопрос, не замалчивать.

3. Каждый открытый пункт отчёта классифицируй:
   - **техническое** — реши сам: одним абзацем решение и что войдёт
     в объём следующей сессии;
   - **политика** (по списку «решать не вправе» из CLAUDE.md) —
     сформулируй вопрос с вариантами и своей рекомендацией;
   - **приёмка** — что владельцу посмотреть глазами, минимальным списком.

4. Перед каждым политическим вопросом проверь DECISIONS.md и BACKLOG.md:
   если уже решено — не задавай, сошлись на запись.

5. Выведи ровно четыре блока и одну строку:
   **Состояние** — 3–5 строк: ветка, коммиты, гейты.
   **Решил сам** — технические решения, каждое с обоснованием в строку.
   **Вопросы владельцу** — только политика; если нет — «нет».
   **Приёмка глазами** — список или «не требуется».
   Последняя строка — предлагаемый объём следующей сессии.

6. ОСТАНОВИСЬ. До ответа владельца — ни коммитов, ни правок,
   ни «пока подготовлю».

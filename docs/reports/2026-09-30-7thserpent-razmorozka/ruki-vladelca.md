### 1. Вливание — push сразу запустит выкладку новыми сторожами

После вашей приёмки глазами — ваше слово «вливай» (или «выливай»). Push в `main` запустит **Deploy 7thserpent.com** сам,
без кнопки Run workflow.

Что сделает робот и что будет в журнале прогона, по шагам:

| Шаг | Строка в журнале |
|---|---|
| Коммит запуска — голова main | `коммит запуска <40 знаков> = голова main — выкладывается он` |
| Сторож папки робота и удалённого index.html | `папка робота: наша сборка (…), записей …, чужих нет; файл подтверждения Google google….html — строка подтверждения сверена, mirror его не трогает (П113)`; затем `index.html на сервере — наш` и `глубина: внутри папок сайта чужого нет …` |
| Первая выкладка? | `первая выкладка: нет — на сервере наша завершённая выкладка …` |
| Домен уже привязан? | `домен отвечает: выкладка обновит живой сайт` |
| Первая выкладка — сборка CI равна принятой | шаг пропущен: выкладка не первая |
| Выкладка по FTPS | файлы сборки; `robots.txt` — те же байты, что сейчас на сервере: ваши правила не меняются; файл подтверждения не трогается |
| Пересчёт на сервере | `на сервере ровно dist/: 165 файлов, ключевые на месте; не в счёте — файл подтверждения Google google….html (корень, П113)` |
| Проверка живого сайта | `44/44 проверок живого сайта www.7thserpent.com` |

**Проверка:**
- у прогона зелёная галочка;
- https://www.7thserpent.com/robots.txt — ваши правила: AhrefsBot … serpstatbot — `Disallow: /`, Googlebot — `Allow: /`,
  строка `Sitemap`;
- Search Console → настройки → подтверждение права собственности — сайт по-прежнему подтверждён.

**Правила `robots.txt` теперь живут в репозитории.** Правка в панели или в файловом менеджере будет затёрта следующей
выкладкой, а `live:check` до неё покажет расхождение («наш файл целиком» — ПЛОХО). Новые правила — пришлите сессии.

**Файл подтверждения Search Console не трогайте.** Если придётся подтверждать сайт заново — загрузите файл, скачанный
из Search Console, а не набирайте его в редакторе панели: сторож сверяет файл побайтно (одна строка, допустим один перевод
строки в конце) и иначе остановит выкладку, назвав, чем файл отличается.

### 2. Кеш статики в панели — шаг 6 листа сессии 23

Статику (CSS, шрифты, картинки, иконки) у этого хостера отдаёт nginx без `Cache-Control` (замер сессии 24). В панели —
правило кеша:
- `/_astro/*` — долгий кеш (год): в именах этих файлов хеш содержимого;
- иконки без хеша в имени — `/favicon.ico`, `/favicon.svg`, `/favicon-16x16.png`, `/favicon-32x32.png`, `/icon-192.png`,
  `/apple-touch-icon.png` — **короткий** кеш (день или меньше).

**Проверка:** в браузере — DevTools → Network → `/_astro/…css` — `Cache-Control` с `max-age` около года; `favicon.svg` —
без `max-age=31536000`.

### 3. Re-run старых прогонов не нажимать; откат — только новым Run workflow со входом отката

- **Re-run не нажимайте** — ни у прогонов #1–#5 (созданы до вливания: их повтор идёт их прежним workflow, без сторожа головы
  `main`), ни у новых. Повтор нового прогона, когда `main` ушёл вперёд, сторож остановит строкой
  `СТОП: коммит запуска … — не голова main (…): это повтор (Re-run, попытка 2) запуска …`.
- **Run workflow — только из `main`** (или из ветки отката, ниже). Ветки `7thserpent-publikacija`, `7thserpent-yashchik`,
  `7thserpent-zhivoy` несут прежний workflow без сторожа головы: запуск из них — откат без входа (сейчас его остановит
  прежний сторож папки на файле подтверждения — **файл подтверждения не удаляйте, что бы ни советовала его строка СТОП**).
  Удалить эти слитые ветки на GitHub — вопрос доклада.
- **Выложить `main` ещё раз** — Actions → **Deploy 7thserpent.com** → **Run workflow** → ветка `main` → все входы `off` → Run.
- **Откат на прежний коммит** (только коммиты этой сессии и позже — вход отката знает только их workflow): попросите
  сессию создать ветку отката на нужный коммит `main`; затем Actions → **Deploy 7thserpent.com** → **Run workflow** →
  «Use workflow from» — эта ветка → **`SERPENT_ROLLBACK` = `on`** → Run. В журнале:
  `ОТКАТ: выкладывается коммит …, голова main — … (вход SERPENT_ROLLBACK = on, П113); что этот коммит — из истории main,
  сторож не проверяет; откат держится до следующей выкладки головы main …`. Проверьте, что коммит — прежний коммит `main`,
  а не неслитая работа.
  - Вход действует только в первой попытке: после красного креста — снова Run workflow из той же ветки со входом, не Re-run.
  - Если оставить ветку `main` и включить вход — строка скажет «отката нет, выкладывается голова».
  - Откат держится до следующей выкладки головы `main`: push в `main` по путям сайта, ядра или корневых манифестов (и из
    сессии первого сайта) или Run workflow из `main` вернут голову. Поэтому после отката — сначала исправление в `main`.

### 4. Красный крест — пришлите строку `СТОП`

Журнал задания без входа мне не виден (GitHub API — 403): пришлите строку `СТОП` упавшего шага (в ней только имена, без
значений секретов). До шага «Выкладка по FTPS» сервер не тронут — сайт работает как был.

Новые строки этой сессии:
- `СТОП: коммит запуска … — не голова main (…): …` — причина в строке:
  - «main ушёл вперёд после запуска» — пока прогон ждал очереди, в `main` пришёл новый коммит: если он меняет сайт,
    его выложит свой прогон; если нет (записи, доклады) — Run workflow из `main`;
  - «повтор (Re-run, попытка N)» — нажат Re-run: новый Run workflow из `main`;
  - «запуск не из main (…)» — Run workflow из другой ветки без входа отката: из `main` или откат, как в шаге 3;
- `СТОП: … в корне робота google….html (…) — …строка подтверждения не сверена` — файл подтверждения на сервере не такой,
  как выдаёт Search Console; причина — в скобках (например, «в начале BOM», «в конце лишнее: …»): скачайте файл заново
  в Search Console и загрузите его в корень `www` поверх этого — загрузкой, не редактором; если в скобках «не скачан» — файл
  не трогайте, новый Run workflow;
- `СТОП: файл подтверждения Google … был в корне до выкладки, а после неё его нет` — выкладка стёрла файл вопреки исключению:
  загрузите его снова из Search Console и пришлите строку;
- `СТОП: голову main не узнать — …` — GitHub не ответил: новый Run workflow (при откате — из той же ветки со входом);
  повторяется — пришлите строку.

## Находки

### P3-R2-MARSHRUT-1 | дефект (малый; на итог не влияет) | `zapas-sizes.js` не проверяет запись A — пропускает потерянную правку

**Что не так.** Шапка обещает: «Ждём: A = расчёт маршрута (как у zanizhenie.js), B = прежнее правило». На деле вердикт считает `ok = |b − прежнее| ≤ 1 && a ≥ прежнее − 1`. Значение A с расчётом маршрута не сверяется. Поэтому если записи с `max()` мертвы или их нет вовсе, получается A = B = прежнее, `ok` = true и итог «НЕ ТАК: 0». Судья не отличает «правка на месте» от «правка потеряна».

**Доказательство.** Опыт 2. Логика оценки из `zapas-sizes.js` взята дословно. Свои контексты, 4425, `/max-payne-3/` и `/max-payne-1/`, 8 окон инструмента. HTML подменялся через `ctx.route`, менялась только строка `sizes` героя (подменено 16 из 16 страниц):
```
M0 без подмены (контроль)           a: 1045 1280 2508 2508 2140 2508 2508 3263 …  НЕ ТАК: 0
M1 правка потеряна: sizes = «(max-width: 1024px) 200vw, 170vw»
                                     a: 780 1280 1282 1600 2048 1742 2448 3263 …   НЕ ТАК: 0  <- проходит
M2 записи с max() мертвы (опечатка «maxx(» в самой строке)
                                     a: 780 1280 1282 1600 2048 1742 2448 3263 …   НЕ ТАК: 0  <- проходит
M3 строка без запасных записей (как 103c0e8, условия max-width)
                                     b: 390 640 641 800 1024 1025 1440 1920 …      НЕ ТАК: 16 (ловит)
```
Правку, которую раунд 1 и сделал (запасные записи), инструмент ловит (M3). Потерю самих записей с `max()` — нет.

**Почему итог в силе.** Проверка идёт мимо вердикта. Числа `a` в `zapas-sizes-1d68052.json` (1045, 2508, 2140, 3263…) совпадают с расчётом маршрута (опыт 1: 1045,55; 2508,39; 2140,49) и с числами раунда 1. Кроме того, `rastyazhenie-sravnenie-r1.txt` (до → после-r1) даёт «лучше 7», например `/max-payne-3/ 800x900@1` 1600 → 1920. При M1 или M2 было бы «лучше 0». Значит, записи с `max()` на 1d68052 живы.

**Что предлагаю.**
- В вердикт добавить `|a − расчёт| ≤ 1`, где расчёт — разбор `sizes` по формуле, как у `zanizhenie.js`. Минимум — требовать `a > прежнее + 1` на клетках, где расчёт выше прежнего: 390x844, 641x900, 800x900, 1024x768, 1025x900 при p ≈ 3,1.
- Писать `hero.sizes` в каждую клетку выгрузки. Сейчас в JSON нет строки, которую проверяли, а сборка названа только словом (тот же класс, что P3-R1-INSTR-8).
- В шапке «Ждём: A = расчёт маршрута» либо проверять, либо заменить на «A не меньше прежнего».

### P3-R2-MARSHRUT-2 | предел (закрыт опытом раунда 2) | чего `zapas-sizes.js` не проверяет

**Что не так.** Опыт проверяет одну модель — «нет ни `max()`, ни `clamp()`». Окна у него: 8 штук, высоты 768–1080. Вне проверки остаются:
- (а) браузер, который понимает `max()`, но не `clamp()`;
- (б) низкие окна, где работают члены с `vh`;
- (в) сканер предзагрузки, то есть двойная загрузка;
- (г) устойчивость метода `naturalWidth` к кэшу внутри документа.

Сама модель «maxx(» верна:
- старый `SizesCalcParser` WebKit отвергает любую функцию, кроме `calc`/`-webkit-calc`, и запись пропускается (`continue`) — так же поступает Chromium с неизвестной функцией;
- все `clamp()` в строке стоят внутри `max()`, поэтому при сломанной `max()` не выживает ни одна `clamp()`. Модель «ни `max()`, ни `clamp()`» точная.

**Доказательство.** Опыт 1 (`opyt-varianty.js`) закрывает все четыре пункта.
- Страницы: `/max-payne-3/`, `/remake/`, `/max-payne-1/`.
- Окна: 25 ширин (320…2560, включая 640/641, 929/930, 1024/1025, 1091/1093/1100) × 5 высот (300, 600, 667, 844, 1080). Всего 375 клеток.
- В 75 клетках — свежая навигация, в 300 — только смена окна в том же документе.
- Значение брали у браузера (`naturalWidth × w / ширина файла`), ожидание — из своего вычислителя по алгоритму HTML «parse a sizes attribute».

| вариант строки | браузер ≠ ожидание (> 1 px) | меньше прежнего правила (> 1 px) | прочее |
|---|---|---|---|
| как есть | 0 | 0 | выше прежнего в 144 клетках |
| нет `max()` («maxx(») | 0 | 0 | равно прежнему правилу в 375 из 375, наибольшая \|Δ\| 0 |
| **`max()` есть, `clamp()` нет** («clampp(») | 0 | 0 | выше прежнего в 42 клетках (записи 3 и 5 уходят в 200vw/170vw, запись 1 жива) |
| без `(min-width: 0px)` | 0 | 0 | равно «как есть» в 375 из 375 |
| без `(min-width: 0px)`, нет `max()` | 0 | 0 | равно прежнему в 375 из 375 |
| строка 103c0e8 | 0 | 0 | **равно «как есть» в 375 из 375**: где `max()` понятна, значения раунда 1 не изменились |
| строка 103c0e8, нет `max()` | 0 | **375** | 100vw: дефект P3-R1-MARSHRUT-1 воспроизводится |

- Кэш: расхождение с ожиданием не больше 1 px и в свежих, и в «несвежих» клетках. Кэшированный больший кандидат метод не портит, как и обещает шапка («какой кандидат ни выбран»).
- Двойная загрузка (опыт 4): 4 страницы × 6 окон и DPR (390x844@3, 800x900@1, 1024x768@2, 1091x600@1, 1440x900@1, 1920x1080@2), каждый раз свежий контекст. Во всех 24 клетках ровно **один** запрос кадра героя, `currentSrc` среди запросов.

**Что предлагаю.** Строку «ПРЕДЕЛЫ» в шапку: «модель одна — без `max()`/`clamp()`; случай "max() есть, clamp() нет", низкие окна и предзагрузка проверены в раунде 2 (P3-R2-MARSHRUT-2)». Инструмент можно не расширять.

### P3-R2-MARSHRUT-4 | мнение | «`(min-width: 0px)`, чтобы за ней могло стоять прежнее `170vw`» — условие нужно для валидности, не для работы

**Что не так.** Комментарий объясняет `(min-width: 0px)` так, будто без него запасная запись `170vw` не сработала бы. Но по алгоритму HTML запись без условия в середине списка — только ошибка разбора по спецификации: если длина разобрана, значение возвращается, если нет — запись пропускается. В Servo/Firefox — то же самое (`SourceSizeOrLength`: разобранная длина без условия возвращается, неразобранная — `Err`, и разбор идёт дальше). Условие делает строку валидной, поведение от него не меняется. Мнение раунда 1 («по спецификации это ошибка разбора, хотя значение возвращается») было точнее.

**Доказательство.** Опыт 1: «без `(min-width: 0px)`» равно «как есть» в 375 из 375. «Без `(min-width: 0px)`, нет `max()`» равно прежнему правилу в 375 из 375. Firefox — по знанию, опытом не проверял.

**Что предлагаю.** «…несёт условие `(min-width: 0px)`: запись без условия по спецификации допустима только последней». Условие оставить: оно безвредно (`min-width: 0px` истинно при любой ширине, включая 0).

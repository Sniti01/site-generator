# Приёмка: исполняемая часть правила

> Выход сессии 1 Фазы 3 (`docs/PLAN-P3.md`), пункт 7 `docs/BACKLOG.md`.
> Само правило приёмки записано в `docs/REUSE.md` §6 и
> `sites/<сайт>/MIGRATION.md` §6 и здесь не меняется — здесь появляется то,
> чем оно исполняется.
>
> **Повод.** Правило опиралось на инструменты, которых в репозитории не было:
> каждая сессия P1 и P2 писала их заново и оставляла вне репозитория. Процедура,
> на которой держится вся серия выносов, была воспроизводима только той сессией,
> что её выполняла, — ровно то свойство, от которого правило должно было увести.

## Что где лежит

| Файл | Что делает |
|---|---|
| `core/accept/manifest.mjs` | снимок `dist/` и побайтовая сверка: подтверждение 1 протокола |
| `core/accept/css-triples.mjs` | разбор CSS в тройки «условие + селектор + объявления», проверка двух из трёх условий перегруппировки `@media`; `--flat` гасит скруты перед разбором |
| `core/accept/pixels.mjs` | попиксельное сравнение кадров: доля субпикселей, максимум, рамка, распределение |
| `core/accept/html-diff.mjs` | приведение скрутов `data-astro-cid-*` — порядковое для выносов, плоское (`--flat`) для расщеплений — и локализация диффы разметки |
| `core/accept/frames.mjs` | порядок съёмки и скрипты страницы; сверка состава, размеров и геометрии снятого набора (П39); с 2026-09-12 — и пикселей по зонам шума `szum.json` эталона, пиксель вне допуска — `exit 1` (П45) |
| `core/accept/szum.mjs` | допуск шума числом: зоны из `<эталон>/szum.json` (кадры, рамка, «только светлые» с порогом яркости, амплитуда `макс`), каждый различающийся субпиксель обязан попасть в зону; чистая `ocenSzum` на разобранных кадрах, CLI `node core/accept/szum.mjs <снятые> <эталон>` (П45) |
| `core/accept/selftest.mjs` | самопроверка: инструменты воспроизводят числа, записанные в отчётах |

Механизм в ядре, запуск у сайта — та же раскладка, что у гейтов:

```
npm run accept -w ac4bf-thewatch.com                          # самопроверка
npm run accept:manifest -w ac4bf-thewatch.com -- snapshot dist ../../../m-before.json
npm run accept:manifest -w ac4bf-thewatch.com -- compare ../../../m-before.json ../../../m-after.json
npm run accept:css -w ac4bf-thewatch.com -- compare before.css after.css
npm run accept:html -w ac4bf-thewatch.com -- localize before.html dist/index.html
npm run accept:pixels -w ac4bf-thewatch.com -- _baseline/baseline-desktop-hero-1440x900.png new.png
npm run accept:frames -w ac4bf-thewatch.com -- protocol
npm run accept:frames -w ac4bf-thewatch.com -- check <кадры> _baseline   # состав, геометрия, пиксели по зонам; exit 1 — вне допуска
npm run accept:szum -w ac4bf-thewatch.com -- <кадры> _baseline             # только пиксели по зонам szum.json
```

## Главное отличие от гейтов: код возврата здесь не приговор

У гейтов `exit≠0` означает регрессию, и билд падает. У приёмки **непустая
диффа — законный шаг 3 протокола**, а не поломка: у расщепления она заведомо
ненулевая. Поэтому ненулевой код инструмента приёмки означает ровно одно:
инструмент не смог сделать свою работу — нет папки, битый снимок,
неподдержанный PNG. **Вердикт читается из вывода, а не из кода.**

Исключение — `selftest.mjs`: он проверяет сам инструмент, и его ненулевой код
означает то же, что у гейта.

**Дописано 2026-09-12 (П45): второе исключение — пиксель вне допуска.**
«Допуск без числа в коде — не допуск, а привычка»: зоны шума эталона живут
числом в `_baseline/szum.json` (кадры, рамка, маска «только светлые» с порогом
яркости, амплитуда `макс`), и `frames.mjs check` — как и `szum.mjs` сам
по себе — сверяет по ним каждый субпиксель каждой пары кадров. Субпиксель
вне зон или выше её `макс`, разошедшиеся размеры, не снятый кадр — **отказ,
`exit 1`**, как у гейта; нет `szum.json` — зон нет, любой дифф — отказ.
Код 2 по-прежнему значит «инструмент не смог» (нет папки, битый PNG,
негодный `szum.json`). Абзац выше не отменён, а сужен: непустая диффа
законна на шаге 3 протокола **внутри записанных зон**; всё вне их читается
из строки `ВНЕ ДОПУСКА …` с числом, максимумом, рамкой и первым субпикселем —
и это приговор. `СДВИГ` геометрии кода не меняет (пункт 26 бэклога открыт:
сдвиг законен и обязан быть объяснён строкой доклада; решение о коде —
владельца): код 0 даёт только сам разбор геометрии; тот же сдвиг обычно
приходит `exit 1` через пиксели — разошедшиеся размеры полного кадра, дифф
оконного. Не-судьи из `ne-sudyi.json` сверяются, но не судятся: строка
«НЕ СУДЬЯ … N различий», своя графа итога, в код не идут — что значит
не-судья при кодовом вердикте, решает владелец. Зона не отменяет
контрольного прогона тем же драйвером: хвост перехода шкалы (макс 88)
допуском не является — при нём пересъёмка.

## Самопроверка: числа берутся из записей, а не из сегодняшнего прогона

Инструмент приёмки, которого никто не видел считающим правильно, — обещание,
а не проверка. Поэтому самопроверка сверяется не сама с собой, а с тем, что
уже записано в отчётах прошлых сессий:

| Число | Откуда запись |
|---|---|
| 50 файлов в `dist/` | `MIGRATION.md` §6, подтверждение 1 |
| один файл CSS в сборке | отчёты P2: «`index.html` и единственный CSS» |
| 331 правило CSS | отчёты `2026-09-07-p2-header`, `-linkcolumns` |
| счёт правил, at-правил и `@media` на рукописном образце | сам образец: пять правил, два at-правила, три вхождения `@media`, два условия ¹ |
| 3 888 000 субпикселей в кадре 1440×900 | отчёты P2 |
| один инвертированный субпиксель находится | отчёт `2026-09-07-p2-cta` |

Расхождение с записью означает, что разошлись либо инструмент, либо сборка,
и разбираться надо **до** того, как инструментом начнут принимать выносы.

¹ **Число `@media` живой сборки самопроверкой больше не проверяется —
решение владельца от 2026-09-09.** Оно двигалось руками каждую сессию:
22 → 24 после расщепления `SiteFooter`, 24 → 26 после `EraLayer`,
26 → 27 после `Hero`. Каждый сдвиг был законен — расщепление разъединяет
одноусловные медиаблоки (`REUSE` §6, условие 3), — но **константа, которую
двигают руками каждую сессию, перестаёт что-либо проверять**.

Взамен проверяется сам счётчик на **рукописном образце**: пять правил, два
at-правила, три вхождения `@media`, два различных условия, причём два блока
идут с одинаковым условием подряд — ровно тот случай, который расщепление
и создаёт. Проверка верна при любой сборке и ловит то единственное, что здесь
и стоило ловить: ошибку разбора. Живую сборку по-прежнему стережёт манифест —
у него это работа, а не побочный эффект.

**Правило приёмки не тронуто ни словом:** `REUSE` §6 и `MIGRATION.md` §6
остались как были.

## Расщепление: приведение скрутов порядковым не бывает

При **выносе** скрут меняет значение, но остаётся одним, и порядковое
приведение `normalizeScopes` работает. При **расщеплении** один скрут
превращается в два-три, нумерация всего, что идёт после первого вхождения,
сдвигается, и вердикта «файлы равны» порядковый режим не даёт ни при каком
исходе.

**Штатный режим для расщеплений — флаг `--flat`**, заведённый сессией 3
Фазы 3 по решению владельца П30 п.1. Правило записано в `REUSE` §6, здесь —
чем оно исполняется:

```
npm run accept:html -w ac4bf-thewatch.com -- localize до.html после.html --flat
npm run accept:css  -w ac4bf-thewatch.com -- compare  до.css  после.css  --flat
```

Три свойства режима, каждое — требование владельца:

1. **Гашение стирает только хеш и ничего больше.** Имя атрибута остаётся,
   ни один другой байт не трогается; приведение имён файлов с хешем — отдельная
   замена, называемая отдельно. Проверяется самопроверкой на образце.
2. **Печатается число погашенных скрутов до и после**, а также раскладка:
   какой скрут уцелел и со сколькими вхождениями, какие появились, какие
   исчезли. Плоское гашение перестаёт различать, чей скрут на элементе, —
   счёт и есть компенсация, без которой режим из судьи становится повязкой
   на глаза.
3. **На расщеплении ожидается 1 → 3**: скрут расщепляемого файла обязан
   уцелеть (он выводится из пути, а обёртка пути не меняет), и рядом обязаны
   появиться ровно два новых. Любое другое число — остановка и разбор.

**Реализация одна на два инструмента:** `flattenScopes` и `scopeLedger`
живут в `html-diff.mjs` рядом с порядковым приведением, а `css-triples.mjs`
их импортирует. Разводить надвое значило бы однажды получить два разных
ответа на один вопрос.

**Самопроверка режима — инварианты, а не числа сборки.** Числа расщеплений
меняются каждой сессией, и константа, которую двигают руками, ничего
не проверяет (пункт 12 `docs/BACKLOG.md`). Поэтому проверяются утверждения,
верные при любой сборке: гашение трогает только хеш; на модели расщепления
скрутов становится 1 → 3, один уцелевает, два появляются, ни один не исчезает.

Режим проверен и на живом расхождении: на артефактах расщепления
`story-row` он воспроизвёл числа, снятые той сессией руками, — 14 → 16
скрутов в разметке, уцелевший `ry73nyyc` со 135 → 35 вхождений, два новых
на 30 и 70, побайтовое равенство после гашения; в листе 16 → 18 скрутов
и ровно 16 разошедшихся троек. Образец применения с числами —
`docs/reports/2026-09-09-p3-storyrow.md`.

## Три решения, принятые при исполнении

**1. Где инструментам жить — в `core/accept/`, запуск у сайта.** Пункт 7
бэклога оставлял вопрос открытым: ядро, отдельная папка уровня репозитория
или скрипты сайта. Взят образец гейтов — механизм общий, ожидания посайтовые, —
с одним отличием, которое пункт сам и называет: приёмка запускается руками
между двумя сборками и билд не роняет. Отсюда разные папки (`core/gates/`
и `core/accept/`) и разное значение кода возврата.

**2. Нормализация скрутов и локализация диффы слиты в один инструмент.**
Бэклог перечислял их порознь, но порознь они не нужны: нормализация существует
ради локализации, а вопрос у них общий — «объясняется ли расхождение скрутами».
Разведённые, они требовали бы промежуточного файла и договора о его формате.

**3. Браузер инструмент не водит, и это решение.** Съёмка кадров происходит
дважды за сессию и руками; тянуть в фабрику драйвер браузера ради двух
запусков — цена, которую проект не платил ни за `xlsx`, ни за PNG (оба
читаются своим кодом). `frames.mjs` делает воспроизводимой саму **процедуру**:
печатает точный порядок шагов и точные скрипты страницы — готовность шрифтов
и изображений, прокрутка до низа и обратно, прокрутка к слою по якорю
(по центру) и к блоку от заголовка (П41), геометрия страницы, — и сверяет
состав, размеры и геометрию снятого набора с эталонным. Драйвер остаётся
снаружи.

**PNG читается своим кодом**, без зависимостей: восьмибитные RGB и RGBA
без чересстрочности — то, что снимает Chromium. Всё прочее роняет инструмент
с внятным сообщением, а не молча считает мусор.

## Чего эти инструменты не делают

- **Не решают, принят ли вынос.** Они меряют. Приговор выносит человек
  по протоколу «полный кадр — сторож, оконный — судья» (П12), и локализация
  обязана идти раньше оконного кадра.
- **Не заменяют манифест скриншотами.** Основная проверка — манифест: он
  покрывает все 50 файлов, включая карты сайта, шрифты и `.webp`-варианты
  на ширины, которые ни один тестовый вьюпорт не выберет.
- **Не гейтят на байтах PNG.** Растеризация шрифтов между прогонами
  не детерминирована; сверяются размеры, доля субпикселей и глаз.

# План P4 — 28 текстов волны 1

*Предложение Code, 2026-09-11, по указанию владельца после закрытия события
перебазирования. Статус: **ждёт слова владельца** по разделу «Что нужно
от владельца для старта». Критический путь проекта — здесь, не в приёмке.*

## Рамка

Дерево волны 1 — 30 страниц `structure.json`. Две готовы: главная (свой
шаблон, `index.astro`) и `/assassins-creed-4-black-flag/` (маршрут, файл
содержания). **Осталось 28** плюс страница приватности вне дерева (пункт 27
бэклога, ранним пунктом по указанию владельца).

«Текст» здесь — не статья в Markdown, а **поля файла содержания**
`src/content/tresc/<слаг>.md`, по одному полю на блок из `blocks[]` страницы
(`content.config.ts`): `lead`, `primary`/`secondary`, `rows[]` (ряды рассказа
с абзацами), `gallery.items[]`, `verdict.body[]`, `toc.items[]`, `byline`,
`related.title`, `cta`. Порядок и набор секций — контракт (`blocks[]`),
слова — файл; маршрут отказывает, если объявленное и напечатанное
расходятся. Судьи уже стоят: сверка `blocks[]` ↔ печать, гейт структуры,
`getPage` на каждом адресе, сторожа `h1` и якорей, пиксельный эталон
страницы игры — **судья для всех страниц маршрута** (П40 шаг 3), новых
эталонов на текст не нужно.

## Способ производства — рекомендация

**«Бриф → черновик → машинная сверка → чтение владельцем», пачками
по одному типу.** Три альтернативы названы в конце раздела.

1. **Бриф собирается машиной, не рукой.** Для каждой страницы инструмент
   (`tools/brief-strony.mjs`, новый, читает только) складывает из структуры
   `h1`, `title`, `description`, `keywords`, `parent`, `related`, `blocks[]`,
   коридор из S4 и **выдержки корпуса**: документы конкурентов кластера
   (`input/corpus/manifest.jsonl` → `groups`, 3543 адреса, 379 хостов, сырой
   HTML в `raw/`) — заголовки, подзаголовки, факты с числами. Бриф — файл
   в `input/briefs/<слаг>.md`, коммитится: то, из чего писался текст,
   должно быть видно через месяц.
2. **Черновик пишет Code** по брифу, на польском, в поля файла содержания,
   голосом уже принятых текстов (главная, страница Black Flag — «Fakty o grach
   są prawdziwe», без таблоидности, вердикт словами без балла — П28).
   Факты о играх — из корпуса и общедоступного знания; каждый факт, которого
   в корпусе нет, **помечается в брифе** строкой «вне корпуса», чтобы владелец
   читал именно их.
3. **Машинная сверка до показа:** `npm run build` (структура, `blocks[]` ↔
   печать, `getPage` на каждом адресе, `h1`, якоря — уже стоят); плюс новый
   гейт **коридора длины** — считает знаки без пробелов по полям файла
   и роняет сборку вне ±15 % (число из S4, записанное в структуру полем или
   в отдельный файл — контракт, владелец); плюс **отчёт покрытия ключей** —
   какие фразы `keywords` встретились в тексте, не гейт, а строка доклада.
4. **Владелец читает пачку**, не смотрит пиксель: у страниц игры судья —
   эталон; глаза нужны один раз на первую страницу каждой новой формы
   (без героя; хаб с лентой) и на факты.
5. **Арт — до текста.** 20 страниц игр печатают героя с ключевым артом;
   `game-art.json` знает пять игр (эпохи главной). `tools/fetch-game-art.mjs`
   умеет тянуть материал из Steam по `appid` — нужны `appid` пятнадцати игр
   и слово владельца, что материал издателя годится всем страницам так же,
   как пяти эпохам. Без арта герой печатает запасной `Viewpoint` — вид,
   которого владелец не принимал.

**Альтернативы.** (а) Владелец пишет сам, Code раскладывает по полям —
честнее по фактам, медленнее в разы; при 28 страницах и коридорах
3–10 тысяч знаков это месяцы. (б) Внешний копирайтер — цена и та же
проблема раскладки. (в) Code без корпуса, из головы — быстро и опасно
фактами; корпус уже скачан (219 МБ) ради этого, не использовать его —
выбросить работу S0–S3. Рекомендация — способ выше: черновик Code
**по корпусу**, владелец — судья фактов, машина — судья формы.

## Приёмка пачки

Каждая пачка — ветка фазы, коммит на страницу, доклад по П33/П36/П38:
`build` зелёный (все сторожа), гейт коридора, отчёт покрытия ключей,
`accept` и `gates` с кодами. Пиксель: страницы игры — против эталона
игры **не снимаются** (эталон судит шаблон, не слова; кадры новых страниц —
только если владелец попросит глазами); первая страница каждой новой
формы — кадры по протоколу в `docs/reports/<слаг>/` **с путями**.
Найденное в шаблоне по ходу текстов — строкой в бэклог, не правкой
(инвариант 3).

## Что нужно от владельца для старта

1. **Приватность:** запись в `structure.json` (адрес `/prywatnosc/`, тип —
   в словаре типов нет служебного, нужен новый или `topic`; `blocks[]`;
   `h1`/`title`/`description`) — контракт; и юридические факты: администратор
   данных, контакт, что собирается (аналитика, cookies) — или указание
   «шаблон RODO без аналитики».
2. **Способ:** слово на «черновик Code по корпусу, владелец — судья фактов»
   или выбор альтернативы.
3. **Вид ветки без героя** (шесть страниц): принять то, что покажет первая
   сборка `/poradniki/od-czego-zaczac/`, или дать этим страницам героя
   с артом — решение о виде, глазами, в пачке 1.
4. **Арт:** материал издателя из Steam для всех двадцати игр, как для пяти
   эпох, — да/нет; `appid` Code найдёт и покажет списком до скачивания.
5. **Коридор длины как гейт:** число в структуру (поле `corridor`) или
   отдельный файл; без слова владельца гейт не заводится, длина — строкой
   доклада.
6. **Подпись:** «Redakcja · Bractwo», дата — день сборки страницы (как
   у Black Flag и главной) — подтвердить или назвать иначе.
7. **Две ленты с содержанием:** `card-rail#the-ezio-collection` у Ezio
   и лента хаба `/poradniki/` — чем наполнять, когда поradników в дереве один.

Без пунктов 1, 2 и 4 пачка 0 не стартует; 3, 5, 6, 7 могут прийти
по ходу, до соответствующих пачек.

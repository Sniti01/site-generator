## Состав

Корень `_baseline/` — главная; следующая страница с эталоном получит
подпапку по слагу с теми же именами файлов (раскладка первого сайта).
Сверка одна: `npm run accept:frames -- check <кадры> _baseline`.

### Главная — корень `_baseline/`, 4 кадра

Главная в объёме каркаса: шапка и подвал ядра, `h1`, лид. Слоёв и блоков
нет — кадры только протокольные (§6: первый экран и полный кадр на двух
вьюпортах). Страница 1440 — **814** px, 390 — **937** px.

| Файл | Размер | Род |
|---|---|---|
| `baseline-desktop-hero-1440x900.png` | 1440×900 | судья: первый экран |
| `baseline-desktop-full-1440.png` | 1440×900 | сторож |
| `baseline-mobile-hero-390x844.png` | 390×844 | судья: первый экран телефона |
| `baseline-mobile-full-390.png` | 390×937 | сторож |

**Полный кадр 1440 побайтово равен первому экрану:** страница (814 px)
короче окна 900, `fullPage` снимает окно. Сторожем он станет, когда
страница вырастет выше окна; тогда его размер разойдётся с эталоном —
это правка вида и пересъёмка по П17, а не шум.

**Зерно в полном кадре лежит только на первом окне.** `Grain` —
`position: fixed; inset: 0`, и `fullPage` рисует его один раз, на первых
844 px кадра 390 (на 1440 — на всём кадре: страница короче окна). Полоса
подвала 844–937 полного кадра 390 снята без зерна: сторож судит её по
чистому фону. Это свойство съёмки (так же у первого сайта, зона 4 его
`szum.json`), не дефект страницы.

**Якорь геометрии без кадра — `#content`** (`<main>`): `offsetTop` 69
на обоих вьюпортах (шапка 68 + волос 1) ловит сдвиг шапки числом, высота
(389,03 на 1440, 313,88 на 390) — сдвиг содержимого главной. Своего кадра
у него нет: он весь в кадрах первого экрана.

### Файлы рядом с кадрами

`geometria.json` — условия съёмки (`clientWidth`, `clientHeight`, `dpr`),
`отступ_блока`, высота страницы и `#content` на обоих вьюпортах; служебные
ключи `снято`, `сборка`, `драйвер`. `ne-sudyi.json` и `szum.json`
не заведены: судьи все, зон шума нет — любой различающийся субпиксель —
отказ (`exit 1`). **Контроль:** три прогона одной сборки тем же драйвером
побайтово равны на всех четырёх кадрах (`frames.mjs check` прогонов 2 и 3
против первого — «0 различий 4», геометрия совпала); эталон — прогон 1.
Так и при первой съёмке (`8da82f4`), и при пересъёмке (`b43b5d6`): зерно
между прогонами не дрожит — зон шума по-прежнему не нужно.

## Драйвер и порядок

Playwright MCP (headless Chromium), вьюпорт 1440×900 → 390×844 без
перезагрузки (П16), `dpr` 1, полоса прокрутки не отнимает ширины
(`clientWidth` 1440/390 — в геометрии). Скрипты страницы `ПРОКРУТКА`
и `ГЕОМЕТРИЯ` — дословно из `core/accept/frames.mjs`, `ГОТОВНОСТЬ` — с
ожиданием картинок под сроком 3 с (обход пункта 19 бэклога; первая съёмка
называла её «дословной» — неточность, найдена раундом 1 «судью судят»
сессии 8), вшитые в код драйвера генератором (динамического импорта
в процессе Playwright MCP нет). Порядок по факту, как у первого сайта
(бэклог 19): `ПРОКРУТКА` до `ГОТОВНОСТЬ`. Прод-превью (`astro preview`),
не dev-сервер. С пересъёмки 2026-09-23 генератор лежит в репозитории —
`docs/reports/2026-09-23-7thserpent-tema-2/instrumenty/kadry-gen.mjs`
(профиль `7s`); перед съёмкой драйвер сверяет сайт на порту по `canonical`
и останавливается, если отвечает чужой. Условия съёмки пересъёмки:
HeadlessChrome 153, `prefers-reduced-transparency: reduce` — нет, зерно
видно (`display: block`, непрозрачность 0.085).

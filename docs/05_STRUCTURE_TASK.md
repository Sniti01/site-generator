# Задача: сессия структуры

Читай `docs/04_STRUCTURE_DECISIONS.md` — там развилки, правила и рамка
контракта; здесь порядок исполнения. Решения владельца по развилкам вноси
в `DECISIONS.md` первым коммитом. Работа — по стадиям, между стадиями
останавливайся, где указана приёмка.

Место в очереди: после текущего шага P3 (инструменты приёмки, пункт 7
бэклога). Расщепления EraLayer/Hero и fetch-art.mjs уступают структуре
и возвращаются после утверждения дерева — к моменту вёрстки страниц.

---

## S0 — Разведка данных (без решений, кроме предложений)

1. Адаптер чтения `input/clustering-google-2026-09-07.xlsx` (источник
   истины — колонки Google; WS не использовать в решениях).
2. Гистограмма Google-сумм кластеров → предложение порогов хвоста
   (Часть C.4) числами, с обоснованием по фактическому распределению.
3. Разметка признаков магазинного интента (Часть C.2) по «% Агрегаторов»,
   составу топа снимка и корзине недобора корпуса → черновой список
   `no_page` с причиной у каждой строки.
4. Раскладка «Некластеризовано»: каждой из 264 фраз — судьба (к кластеру /
   новая тема / exclusions / no_page) с уверенностью. Отдельно назови
   кандидатов в тему карты мест, если найдутся.
5. Выход S0 — один документ с пачками на подтверждение владельцу:
   пороги, no_page, судьбы «Некластеризовано». **Остановка: подтверждение
   пачек.**

## S1 — Контракт и валидатор

1. Схема `structure.json` по рамке Части B и прецедентам `REUSE.md` §5.
2. Валидатор — гейт со свойством ронять сборку: учёт каждого запроса ровно
   один раз; уникальность `title/description/h1` глобально; сироты; глубина
   `MAX_DEPTH=2`; пересечение топов ≥50 % (антиканнибализация); `blocks[]`
   только из словаря имён ядра (kebab).
3. Словарь умолчаний «тип → блоки» — данными ядра, начальное наполнение
   из BLOKI 7dtd и блоков ac4bf, с пометкой `type-default`.

## S2 — Дерево

1. Применить правила судеб (подтверждённые в S0) ко всем кластерам →
   `structure.json`: все страницы обеих волн, `wave` проставлен по критерию
   Части D, карта мест — `owner: true`.
2. Проверка связности волны 1: родитель каждой страницы в волне; CTA
   главной ведёт на существующую страницу волны.
3. Выход — дерево в читаемом виде (страница, url, тип, волна, кластер,
   Google-сумма, покрытие корпуса) + `structure.json`, валидатор зелёный.
   **Остановка: приёмка дерева владельцем — главная точка сессии.**

## S3 — Анатомия корпуса (после утверждения дерева)

1. Два прохода по одному корпусу (пункт 1 бэклога): план содержания
   (перенос конвейера 1weekinvr: медиана объёма ±15 %, дерево H2, гэпы,
   `VOLUME_MIN_DOCS=4`) и анатомия страниц (крошки, оглавление, похожие,
   FAQ, таблицы, schema.org) с порогом частоты — элемент у ≥7 из 10 —
   обязателен; 4–6 — на решение; корзина покрытия учитывается: low —
   только план содержания.
2. Выход — заполнение `blocks[]` страниц волны 1 (`source: anatomy`,
   `confidence`, `evidence`), неопознанное — в `docs/UNRESOLVED.md`
   строками, не тихими пропусками.
3. Извлекается структура страниц, не текст: чужие формулировки не
   сохраняются и не цитируются нигде, включая примеры. Корпус — только
   чтение.

## S4 — Финализация волны 1

`no_page`, `exclusions` — числа сходятся с учётом каждого запроса; открытые
вопросы по жанру `/review`.

## ФАЗА 2 — Ядро фабрики

Собрать скелет по §7 модели:

1. **Структура репозитория** `core/ + sites/ + docs/ + skills/`.
2. **Контракт `structure.json`** — схема + валидатор.
3. **Адаптеры**: `landing`, `clusters` (рабочие) и `seo-pipeline`
   (заглушка с фиксированным контрактом — конвертер ещё делается, менять потом
   должно быть можно только внутри адаптера).
4. **Библиотека блоков** — перенести подтверждённое из `REUSE.md`.
   У каждого блока: имя, назначение, SEO-роль, контракт данных, минимум 2 варианта
   подачи (чтобы страницы одного типа не были близнецами).
5. **Шаблоны типов страниц** из реестра §5.
6. **SEO-слой**: шаблоны title/description, breadcrumbs, canonical, sitemap, robots,
   OG, schema.org, движок перелинковки внутри кластера и между кластерами.
7. **Три режима** (`normal` / `auto` / `interview`) как команды конвейера.
8. **`CLAUDE.md`** в корне: как запускается конвейер, что нельзя трогать,
   куда писать `DECISIONS.md`.

### Отдельное правило для блоков, вынимаемых из ac4bf
Выносим **по одному**. После каждого выноса — пересборка главной и сверка с эталонными
скриншотами из `_baseline/`. Расхождение = откат выноса, а не правка главной.

## ФАЗА 3 — Достройка ac4bf-thewatch.com

Структуры у сайта ещё нет, поэтому фаза делится надвое.

**3a — что можно делать без структуры:**
- дизайн-система сайта на основе уже сделанной главной (токены, типографика, сетка);
- доведение главной: недостающие блоки, мобильная вёрстка, состояния, микровзаимодействия;
- SEO-каркас: мета-шаблоны, OG, robots, заготовка sitemap;
- каркасы типов страниц из брифа — пустые, но рабочие.

**3b — после того, как я дам структуру и (возможно) тексты:**
полный прогон стадий 1→6 модели: `structure.json` → карта блоков → дизайн через
`impeccable` → раскладка текстов → генерация всех страниц → QA.

Обязательно по ходу:
- `DECISIONS.md` — каждое решение, принятое за меня (особенно в `auto`);
- разбор референсов письменно **до** дизайна: что взято, что не взято, почему;
- карта блоков по типам страниц **до** вёрстки — показать её;
- если тексты готовые — раскладка по §6 модели, полотна текста недопустимы.

## Чек-лист QA (стадия 6)

**SEO**
- [ ] один H1 на страницу, иерархия H2/H3 повторяет логику кластера
- [ ] title/description уникальны, по шаблону, в лимитах
- [ ] canonical, breadcrumbs, sitemap.xml, robots.txt, OG/Twitter
- [ ] schema.org по типу страницы
- [ ] перелинковка: нет страниц-сирот, нет тупиков
- [ ] URL — по структуре, без мусора, без дублей
- [ ] alt у всех изображений

**Контент**
- [ ] нет текстового блока длиннее ~900 знаков без визуального разрыва
- [ ] два одинаковых блока подряд отсутствуют
- [ ] страницы одного типа отличаются друг от друга
- [ ] готовые тексты не переписаны (или изменения зафиксированы)

**Дизайн и техника**
- [ ] мобильная вёрстка проверена
- [ ] контраст проходит по доступности
- [ ] Lighthouse: perf/SEO/a11y ≥ 90
- [ ] нет битых ссылок и пустых блоков

## Правила работы

- Не начинать фазу, пока предыдущая не подтверждена.
- Наработки по ac4bf-thewatch.com — источник истины, а не черновик на выброс.
- Не изобретать структуру, если она задана брифом.
- Переиспользовать из `core/` прежде, чем писать новое.
- Улучшение, годное всем сайтам, переносится в `core/` отдельным коммитом,
  а не остаётся в теме одного сайта.
- Всё, что решено самостоятельно, — строкой в `DECISIONS.md`.

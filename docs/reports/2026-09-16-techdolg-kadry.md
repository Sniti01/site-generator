# 2. `core/media/fetch-art.mjs` — ядро, отдельным коммитом (`5a519ff`; бэклог 50 п. 3–5)

**Автор Commons (п. 3).** Поле `Artist` — HTML шаблонов, и подвал печатал
его дословно. Измерено на файлах витрины (сырые ответы API, записаны
в `--selftest`): шаблон `{{unknown}}` — `Unknown author<span
style="display: none;">Unknown author</span>` → после зачистки тегов
«Unknown author Unknown author» (`foto-kopernik`); Bundesarchiv —
`Unknown<span …>Unknown </span>` → «Unknown Unknown»; NARA —
«…or not provided» в `div`; гравюры Чёрной Бороды — абзац со сноской
`<a class="external autonumber">[1]</a>`; `Credit` Kopernika — список
из трёх URL.

Чистка `autorZ` — механическая только там, где ошибка детерминирована:
скрытые span и сноски снимаются **до** зачистки тегов; «Unknown
author» / «Unknown» / «Anonymous» (и «or not provided») — отсутствие автора,
тогда идёт `Credit` (архив), если это не список URL и не абзац (≤ 80
знаков); иначе «nieznany», как и прежде при пустом поле. **Чего инструмент
не делает — не режет предложений:** граница «P. Hughes» неотличима от

слота** `art.json` (тип `core/media/art.ts`) с приоритетом над Commons:
текст редакции, записываемый инструментом в `art-credits.json`, как любой

# 8. Факты, важные будущим сессиям

- Commons отдаёт те же байты при перекачке файла с тем же `iiurlwidth`
  и `crop`; `sharp` 0.35.4 детерминирован — `--force --only` по слоту
  безопасен для git-истории файлов, меняет только атрибуцию.
- Поле `Artist` у архивов (Bundesarchiv, NARA, LoC) — шаблон
  `{{unknown}}` со скрытым span; настоящая атрибуция лежит в `Credit`.
  У музейных загрузок (BnF, Yale) `Artist` несёт роль из каталога
  («Cartographe du modèle») — законная строка, инструмент её не трогает.
- Транспорт Bash: аргумент с ведущим `/` (адрес страницы) конвертируется
  MSYS в путь `C:/Program Files/Git/…` — инструменты с адресами запускать
  из PowerShell или с `MSYS_NO_PATHCONV=1` (шапка `s2-hero.mjs`).
- Новые файлы в `sites/` пишутся LF инструментом Write и переводятся
  в CRLF своим скриптом до первого `git add` — это не «перевод окончаний
  существующего файла» (инвариант 1), файл в индекс входит уже CRLF.
- `git add --renormalize .` **стажирует** изменённые файлы — проверку
  «не трогает ничего» делать перед коммитом тех же файлов, а не как
  отдельный шаг с чистым индексом.

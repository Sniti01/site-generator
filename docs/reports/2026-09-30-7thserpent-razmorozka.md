## 4. Файл подтверждения Google — правило сторожей (дифф)

Ваше правило (П113): сторож пропускает в корне `google<код>.html`, если внутри — строка подтверждения с тем же именем;
`mirror --delete` его не стирает; пересчёт не считает; иное — стоп. Сделано так (`zamery/diff-storozha.txt`,
`zamery/diff-workflow.txt`):
- **имя** — файл корня `google` + буквы и цифры + `.html` (форма Google; во всех найденных образцах — 16 шестнадцатеричных).
  Папка или ссылка с таким именем, имя другой формы — стоп, как было;
- **скачивание** — шаг сторожа папки берёт такие файлы вместе с главной и картой (`--include-glob=google*.html`);
  сторож папки получает папку скачанного;
- **сверка** — содержимое ровно `google-site-verification: <то же имя>`, допустим один перевод строки в конце (LF или
  CRLF). Иначе — стоп. Причина называется без содержимого файла: «файл пуст», «в начале BOM», «в конце лишнее после
  строки подтверждения: пробел, LF…», «внутри имя другого файла…», «не строка подтверждения». Совет — скачать файл
  заново в Search Console и загрузить поверх; «не скачан» — файл не трогать, новый Run workflow;
- **двойник имени** с невидимым знаком по краю (после обрезки имя в списке дважды) — стоп. Для имён сборки тот же класс
  остаётся пределом (бэклог 74 п. 4);
- **такой файл в самой сборке** — стоп: `mirror` его не выложил бы;
- **`mirror`** — `-x '^google[0-9A-Za-z]+\.html$'` (тот же образец, что у сторожа) перед исключением главной;
- **пересчёт** — файлы Google корня не считает и называет в строке прохода. Со списком корня до выкладки
  (`remote-root.txt`) файл, сверенный до `mirror`, обязан остаться, новый — стоп. Это страховка на случай, если `-x`
  у lftp на этом сервере поведёт себя не так, как в документации: тогда пропажа файла не пройдёт молча.

Глубина корень не судит, как было. Файл Google глубже корня — чужое: стоп глубины и пересчёта с прежними пределами.
Прямые файлы `_astro/` (ассеты прежних сборок) и служебные папки `.well-known/`, `cgi-bin/` глубина пропускает, как
и раньше; файл Google прямо в `_astro/` потом стирает `mirror`.

## 5. Сторож «коммит запуска = голова `main`» (дифф)

Новый шаг workflow — сразу после `setup-node`, до секретов, корпуса, сборки и любого lftp:

```yaml
- name: Коммит запуска — голова main
  env:
    GIT_TERMINAL_PROMPT: '0'
    SERPENT_ROLLBACK: ${{ github.run_attempt == 1 && inputs.SERPENT_ROLLBACK || 'off' }}
  run: |
    git ls-remote "$GITHUB_SERVER_URL/$GITHUB_REPOSITORY" refs/heads/main > golova-main.txt 2> golova-main-oshibki.txt || echo "…" >> golova-main-oshibki.txt
    node $SITE/tools/storozha-vykladki.mjs golova golova-main.txt golova-main-oshibki.txt
```

- **Равны** → `коммит запуска <…> = голова main — выкладывается он`.
- **Не равны** → стоп с обоими коммитами и причиной по запуску: «main ушёл вперёд после запуска», «повтор (Re-run,
  попытка N)» или «запуск не из main (<ref>)». Сервер не тронут.
- **Вход отката `SERPENT_ROLLBACK`** (выбор `off`/`on`, по умолчанию `off`; только в первой попытке запуска — как
  `SERPENT_DOMAIN_BOUND`) → «ОТКАТ: выкладывается коммит …, голова main — …; что этот коммит — из истории main, сторож
  не проверяет; откат держится до следующей выкладки головы main». Если со входом запустить из головы `main` (коммит
  запуска = голова в момент сверки), строка скажет «отката нет».
- **Голову не узнать** (сбой git) → стоп с первой строкой ошибки; при откате совет — «из той же ветки или метки со входом».

**Пределы** (шапка workflow и описание входа; бэклог 74 п. 6–8, 72 п. 4):
- сверка одна, в начале: push в `main` за время сборки этот прогон не остановит — голову выложит следующий прогон;
- push в `main` вне путей выкладки (`docs/`, первый сайт), пока прогон ждёт очереди или идёт к сверке, — стоп «main ушёл
  вперёд после запуска». Такой push нового прогона не запускает: сайт ждёт Run workflow из `main`. Пропускать ли такой
  запуск — решение на потом (74 п. 8). **Поэтому при вливании:** пока прогон вливания не прошёл шаг сверки, в `main`
  больше ничего не пушить;
- откат — только на коммиты с этим workflow (вливание этой сессии и позже);
- Run workflow из старых веток и Re-run прогонов #1–#5 идут прежним workflow без сторожа. Сейчас их останавливает прежний
  сторож папки на файле подтверждения — **файл не удалять**, что бы ни советовала его строка СТОП.

Первому сайту — в сессии 26 (ваше слово).

## 10. Открытые вопросы

### Технические — решены

1. **`public/robots.txt` — записью байтов тела**, а не набором текста: sha256 файла = sha256 тела сервера
   (`instrumenty/robots-v-public.mjs`).
2. **Тексты `check-live` под ваш файл** — в объёме «`check-live` и его пробы — под новый файл» (П113 «Как прочитано»
   п. 8). Логика не менялась.
3. **Строгость образца имени файла Google — буквы и цифры, а не только 16 шестнадцатеричных:** содержимое сверяется
   побайтно, поэтому шире имя вреда не несёт, а ложный стоп на необычном коде исключён.
4. **Пересчёт со списком корня** (SV25-O-1) — страховка без нового решения. Это проверка вашего же слова «mirror --delete
   его не стирает».
5. **Одна сверка головы, в начале** (GL25-O-1) — оставлена. Вторая сверка перед `mirror` растянула бы ложный стоп
   «main ушёл вперёд» на всё время сборки, а окно гонки само закрывается следующим прогоном. Предел — в шапке и бэклоге.
6. **Пределы `check-live` без правки логики** (CL25-P-2, P-5, P-6, Z-2, Z-5, Z-6) — тестами `todo`, как в прежних сессиях.
7. **Проза шапки — одним скептиком без падающих проб** (П113 «Как прочитано» п. 11): логики нет.
8. **`accept` и `gates` — отдельным инструментом после приёмки** (`instrumenty/p33.mjs`): только запуск и журналы, своих
   вердиктов нет; порядок «коммит, сборка, пробы» — коммит инструмента, сборка, затем `accept` и `gates`.

### Политические — для вас

**Вопрос 1. Блок хостера поверх ваших правил** (CL25-P-1). Если хостер снова включит «adm.tools Managed content», блок
закроет GPTBot, который вы не закрывали, и ещё раз — уже закрытых вами ботов. `live:check` сейчас пройдёт 44 из 44 со
справкой «блок хостера … отключается в панели хостера»: в зелёном прогоне CI справку никто не читает.

| Вариант | Что это | Цена |
|---|---|---|
| (А) Оставить | блок хостера — законная форма, как вы сказали про образец сессии 24 | возврат блока пройдёт молча |
| **(Б) Красный крест** (рекомендую) | блок хостера поверх ваших правил — отказ `live:check`; образец сессии 24 остаётся в пробах как история и ждёт отказа | меняется ваше слово П113 «законная форма»; правка `check-live` — отдельной сессией с «судью судят» |

Рекомендация — **(Б)**: вы отключили блок, чтобы правила были вашими; его тихое возвращение — повод для красного креста.

**Вопрос 2. Несколько файлов подтверждения Google** (SV25-O-2). По букве П113 проходит любой `google<код>.html` со своей
строкой. Значит, проходит и файл чужого аккаунта Google: его хозяин стал бы подтверждённым владельцем сайта в Search
Console.

| Вариант | Что это | Цена |
|---|---|---|
| (А) Ровно один файл в корне | два и больше — стоп с именами | законная смена файла — через удаление старого |
| **(Б) Закрепить имя вашего файла в сайте** (рекомендую) | вы называете имя (оно не секрет — файл открыт по адресу); проходит только оно | нужна правка сторожа отдельной сессией; до неё — как сейчас |
| (В) Как есть | проходит любой верный файл, имя печатается в журнале | чужой файл виден только в журнале |

Рекомендация — **(Б)**. Назовите имя — сессия заодно одной GET сверит байты вашего файла до следующей выкладки.

**Вопрос 3. Откат — только на коммит из истории `main`?** (GL25-O-2). Вход `SERPENT_ROLLBACK` сейчас пропускает любой
коммит, в том числе неслитую ветку впереди `main`. Строка ОТКАТ это прямо говорит, но не останавливает.

| Вариант | Что это | Цена |
|---|---|---|
| (А) Как есть | откат — любой коммит; строка ОТКАТ говорит «что этот коммит — из истории main, сторож не проверяет» | неслитая работа может уйти на сайт по ошибке |
| **(Б) Только история `main`** (рекомендую) | шаг головы забирает историю `main` и проверяет предка; не предок — стоп | сужает ваше слово «со входом выкладка идёт»; отдельной сессией (вместе с первым сайтом) |

**Вопрос 4. Старые слитые ветки на GitHub** (GL25-O-3). `7thserpent-publikacija`, `7thserpent-yashchik`,
`7thserpent-zhivoy` несут прежний workflow без сторожа головы. Run workflow из них — откат без входа. Сейчас его
останавливает прежний сторож папки на файле подтверждения.

| Вариант | Что это | Цена |
|---|---|---|
| **(А) Удалить эти три ветки** (рекомендую) | ваши руки на GitHub, страница веток; история цела — все три ветки уже в `main` | — |
| (Б) Оставить | их держит прежний сторож, пока в корне лежит файл Google | защита случайная |

На будущее, в любом варианте, — окружение GitHub с правилом веток и секретами выкладки в нём: запуск не из `main` секретов
не получит (бэклог 74 п. 6).

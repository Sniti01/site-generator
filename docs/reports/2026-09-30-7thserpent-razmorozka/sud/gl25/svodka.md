**Держит (скептики):**
- ближайшее вливание (один push перемоткой): коммит запуска = голова → проход; ложного стопа нет, если второй push не придёт
  в `main` раньше шага сверки;
- Re-run (весь и «failed jobs») прогона после вливания, когда `main` ушёл вперёд, — стоп до секретов; вход отката в попытке
  2+ — `off`, Re-run отката — стоп; push без входов — `off`;
- обхода кода 2 нет: откат включает только точное `on` («on » с пробелом, кириллическая «о», `true`, `ON`, `yes` — код 2);
  `GITHUB_SHA` прописными или в 64 знака — код 2;
- разбор вывода git строгий: ровно одна строка «40 строчных шестнадцатеричных<TAB>refs/heads/main» (CRLF допустим); BOM,
  пробелы, NUL, U+2028, 41 или 64 знака, кириллица, `^{}`, вторая строка — стоп и со входом отката;
- строки в журнал безопасны: 12 порч stderr (`::error::`, `::add-mask::`, `##[`, ANSI, U+202E, U+2028, 10 000 знаков, «:::»)
  дают одну строку без команд раннера и невидимых знаков;
- шаг как написан (блок run под `bash -e`, без `.git`): с сетью — проход; без сети — `|| echo` держит оболочку, сторож
  печатает СТОП с первой строкой ошибки git;
- мутанты сторожа головы (CRLF недопустим, лишний перевод строки, предупреждение как стоп, обязательный файл ошибок, «ОТКАТ»
  на голове, пустой вход как ошибка) пойманы пробами.

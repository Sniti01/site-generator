# Контракт `structure.json` и гейт структуры

> Выход стадии S1 `docs/05_STRUCTURE_TASK.md`. Рамка полей задана Частью B
> `docs/04_STRUCTURE_DECISIONS.md`, решения — П24 и П25 в `DECISIONS.md`,
> прецеденты — `docs/REUSE.md` §5. Здесь коротко: что где лежит, что именно
> проверяется и почему проверка устроена так.

## Где что лежит

| Файл | Что это |
|---|---|
| `core/structure/schema.json` | контракт: поля, закрытые списки, числа правил |
| `core/structure/blocks.json` | kebab-словарь имён блоков — перенос таблицы Р4 `REUSE` §1.1 |
| `core/structure/type-blocks.json` | умолчания «тип → блоки» (развилка 4) |
| `core/structure/clustering.mjs` | читатель выгрузки семантики; общий для фабрики |
| `core/gates/check-structure.mjs` | гейт: считает, печатает, роняет сборку |
| `core/structure/fixtures/selftest.json` | 22 случая самопроверки валидатора |
| `sites/<сайт>/structure/structure.json` | сама структура сайта — данные сайта |

Раздел ответственности тот же, что у гейтов ресурсов и контраста: **счёт
в ядре, объявление в данных сайта.** Какую выгрузку читать, ядро не знает —
на неё указывает поле `site.semantics` внутри структуры.

## Девять проверок гейта

1. **Структура файла** — обязательные поля, закрытые списки (`type`, `wave`,
   `status`, `source`, `confidence`), форма адреса. Опечатка в значении
   ловится здесь, а не в вёрстке.
2. **Учёт: каждый запрос ровно один раз** — страница, `exclusions` или
   `no_page`. Единственная известная защита от осиротевшей семантики
   (`REUSE` §5.1, п.3); правило взято у 7dtd дословно.
3. **Сверка `keywords` с выгрузкой посимвольно.** Запрос, которого
   в выгрузке нет, — ошибка. На пробном прогоне это сразу поймало подмену:
   в структуру попала «Топ-фраза (Google)» с листа «Кластеры», а она
   нормализована и отличается от фразы кластеризации.
4. **Глобальная уникальность `title`, `description`, `h1`** — два одинаковых
   `title` видно только в индексе Google, то есть через месяц.
5. **Сироты и корень** — `parent` и `related` указывают на существующие
   страницы, страница без родителя ровно одна.
6. **Адрес не расходится с родителем** — `parent` равен пути, полученному
   из `url` отбрасыванием последнего сегмента. Иначе крошки и адрес
   рассказывают о дереве разное.
7. **Глубина не больше `MAX_DEPTH = 2`.**
8. **Связность волны 1** — родитель страницы волны 1 сам в волне 1
   (Часть D.1). Проверка стоит здесь, а не в S2: место у неё одно.
9. **Антиканнибализация** — пересечение топов кластеров двух страниц ниже
   порога 50 %. Делитель — меньший из топов: четыре общих адреса при топе
   из четырёх — это полное совпадение, а не 40 %.

Плюс `blocks[]`: имя только из словаря ядра и только уровня «секция» —
`grain` или `site-header` в `blocks[]` не станут; `evidence` разрешён
только при `source: anatomy`.

## Что добавлено к рамке Части B и почему

Три поля, которых в Части B нет, взяты из прецедентов `REUSE` §5 —
названы здесь, чтобы добавление не выглядело самоуправством:

- **шапка `site`** (`domain`, `lang`, `semantics`, `semantics_date`,
  `total_queries`) — прецедент 7dtd. Без неё гейт не знает, какую выгрузку
  сверять, а `total_queries` ловит подмену выгрузки: число в шапке
  сверяется с фактическим.
- **`volume`** — прецедент §5.1, п.5: сумму частотностей пишет скрипт,
  руками не трогают.
- **`template`** — §5.2: «чего нет ни у кого и что придётся завести»,
  вместо `if slug == HOME_SLUG`. Поле необязательное: пока тип и шаблон
  совпадают, его нет.

**Закрытый список `type` — предложение, а не решение.** Семь значений:
`home`, `hub`, `game`, `guide`, `topic`, `map`, `legal`. Список закрывается
вместе с приёмкой дерева на S2 — раньше его закрывать нечем: типы становятся
настоящими, когда видно, сколько страниц каждого из них существует.

## Пустое дерево и отсутствие файла

**Пустое дерево законно** и означает этап до S2: контракт есть, страниц
ещё нет. Гейт проверяет шапку и проходит.

**Отсутствие файла не законно.** Его нельзя отличить от забытого — тот же
довод, что у гейта ресурсов: пустой список правильный, пропавший файл нет.

## Как запускать

```
npm run gates -w ac4bf-thewatch.com     # все гейты, структура среди них
node core/gates/check-structure.mjs sites/ac4bf-thewatch.com
node core/gates/check-structure.mjs --selftest
```

Самопроверка — не украшение: **гейт, которого никто не видел падающим, —
обещание, а не проверка.** 22 случая: одно правильное дерево и по случаю
на каждое правило, каждый получен правкой правильного, поэтому нарушение
в нём ровно одно.

## Что будет на S2

По подтверждённым пачкам S0 (П25) строится дерево: все страницы обеих волн,
`wave` по критерию Части D, карта мест с `owner: true`. Гейт при этом
включается целиком — учёт 1426 запросов, каннибализация, связность —
и дерево выносится владельцу на приёмку глазами.
